**1. Какие HTML5-атрибуты используются для клиентской валидации и какую функциональность они предоставляют?**

Основные атрибуты:
*   required — делает поле обязательным для заполнения.
*   minlength / maxlength — задают минимальную и максимальную длину текста.
*   min / max / step — ограничивают диапазон значений для чисел, дат и времени.
*   type (например, email, url, tel, number) — активирует встроенные проверки формата данных.
*   pattern — задает регулярное выражение, которому должно соответствовать введенное значение.
Эти атрибуты позволяют браузеру проверять данные до отправки формы на сервер без использования JavaScript.


**2. В чем разница между novalidate атрибутом формы и отключением валидации через JavaScript?**

Атрибут novalidate на теге <form> отключает встроенную браузерную валидацию и блокировку отправки формы. При этом форма отправится на сервер, даже если поля не заполнены или заполнены неверно. Отключение валидации через JavaScript (например, если скрипт не загрузился) означает, что кастомные проверки не выполнятся, но если атрибута novalidate нет, браузер применит свою встроенную валидацию и не даст отправить неверно заполненную форму.


**3. Как правильно связать <label> с полем ввода и почему это важно для доступности?**

Связь осуществляется через атрибут for у тега <label>, значение которого должно строго совпадать с атрибутом id соответствующего поля ввода (<input>, <textarea> или <select>). Это важно для доступности (Accessibility): программы экранного доступа (скринридеры) зачитывают текст лейбла, когда пользователь фокусируется на поле. Также это улучшает UX, так как клик по тексту лейбла переводит фокус в поле ввода (особенно полезно для радиокнопок и чекбоксов).


**4. Какие типы полей input наиболее подходят для разных видов данных (email, телефон, пароль и т.д.)?**

*   type="email" — проверяет наличие символа @ и домена, на мобильных открывает клавиатуру с нужными символами.
*   type="tel" — на мобильных устройствах открывает цифровую клавиатуру (сам формат нужно проверять через pattern).
*   type="password" — скрывает вводимые символы точками/звездочками.
*   type="text" — для обычного текста.
*   type="number" — для чисел (добавляет стрелочки для изменения значения).
*   type="date" — открывает встроенный календарь.
*   type="url" — проверяет наличие протокола и корректность ссылки.


**5. Как работает валидация с помощью pattern атрибута и в каких случаях его следует использовать?**

Атрибут pattern принимает регулярное выражение. Браузер проверяет, полностью ли введенное пользователем значение соответствует этому выражению. Его следует использовать, когда стандартных атрибутов type или minlength/maxlength недостаточно для проверки специфичного формата (например, сложные пароли, серии паспортов, почтовые индексы конкретной страны или строгий формат телефона).


**6. Какие события JavaScript используются для реализации валидации в реальном времени и почему?**

*   blur — срабатывает, когда пользователь уходит из поля. Идеально для первичной валидации, чтобы не раздражать пользователя ошибками прямо во время набора текста.
*   input — срабатывает при каждом изменении значения. Хорошо подходит для динамической очистки сообщений об ошибках, как только пользователь начинает исправлять поле.
*   change — используется для чекбоксов и селектов, так как они не всегда генерируют событие input.


**7. Как обеспечить доступность сообщений об ошибках для пользователей скринридеров?**

Необходимо использовать ARIA-атрибуты:
*   aria-live="polite" на контейнере с ошибкой — заставляет скринридер зачитывать появившийся текст ошибки, не прерывая текущие действия пользователя.
*   aria-describedby="id-ошибки" на самом поле ввода — связывает поле с текстом ошибки, чтобы при фокусе на поле скринридер зачитывал и правило заполнения.
*   Также можно динамически добавлять атрибут aria-invalid="true" в JavaScript, когда поле не проходит валидацию.


**8. В чем преимущества использования fieldset и legend для группировки полей формы?**

С точки зрения семантики, fieldset группирует логически связанные элементы управления (например, блок контактных данных или радиокнопки выбора пола), а legend дает этой группе заголовок. Для доступности это критически важно: скринридеры зачитывают текст из legend перед тем, как начать перечислять поля внутри группы, что дает пользователю контекст. Визуально это также помогает разделить длинную форму на логические блоки.


**9. Как реализовать кастомную валидацию для сложных случаев (например, подтверждение пароля)?**

Нужно написать отдельную функцию на JavaScript, которая сравнивает значения двух полей (password.value === confirmPassword.value). Эту функцию следует вызывать при событии input (для мгновенной реакции) и при событии submit (для блокировки отправки). При несовпадении полю confirmPassword добавляется класс ошибки (например, .error) и выводится соответствующее сообщение в span под полем.


**10. Какие методы CSS используются для визуального отображения состояний валидности/невалидности полей?**

В CSS используются псевдоклассы:
*   :valid — стилизует поле, когда оно заполнено верно.
*   :invalid — стилизует поле при ошибке. Чтобы ошибки не подсвечивались на пустых полях при загрузке страницы, применяют трюк: input:invalid:not(:focus):not(:placeholder-shown).
*   :required / :optional — позволяют стилизовать обязательные и необязательные поля.
*   Дополнительно используются кастомные классы (например, .error), которые добавляются через JavaScript для более точного контроля цветов и теней.
